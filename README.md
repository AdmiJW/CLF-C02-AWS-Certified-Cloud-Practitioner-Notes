# CLF-C02 Study Notes

Personal notes for the AWS Certified Cloud Practitioner exam, written and shared by [AdmiJW](https://github.com/AdmiJW). This is an evolving collection.

**Read the website:** https://admijw.github.io/CLF-C02-AWS-Certified-Cloud-Practitioner-Notes/

## Notes and attachments

Keep editing the original Markdown files in Obsidian. The website discovers root files named **NN - Topic.md**, using a two-digit number for chapter order. The introduction is **00 - Course Introduction.md**.

Add the next numbered root file, commit it, and push to **master**. Pages, navigation, reading estimates, and search are regenerated automatically. Numbered folders are not part of the current discovery convention. Frontmatter and manual route registration are not required.

The website strips only the ordering prefix from the displayed title and creates lowercase hyphenated URLs. Renaming a chapter title changes its URL. Colliding URLs stop the build.

Keep images in their original locations, such as **Attachments/**, and use relative Markdown URLs. Every build publishes referenced images, preserving filename case and encoding spaces and Unicode. Missing local images stop deployment.

Source headings, paragraphs, tables, questions, and answers remain unchanged. Heading normalization and permalinks are applied only to rendered pages.

## Local development

Requirements: Node.js 22 (at least 22.12) and npm. Run commands from **site/**:

    cd site
    npm ci
    npm test
    npm run check
    npm run dev

For production verification:

    npm run build
    npm run preview

Open the repository base shown by the server:
http://localhost:4321/CLF-C02-AWS-Certified-Cloud-Practitioner-Notes/

Search is generated by production builds. Run **npm run build** before previewing search; the development server alone does not generate the index.

The full build generates HTML, copies attachments, runs Pagefind, and validates output. Source discovery and route rules are shared with the output validator; no fixed chapter count is used.

## Publishing

GitHub Pages uses **Settings → Pages → GitHub Actions**. Pushes and pull requests to **master** run the content tests, type checks, HTML/attachment build, search indexing, and output validation. Successful pushes to **master** and manual runs on **master** deploy **site/dist**; pull requests validate only.

Markdown and attachment changes trigger the workflow even when nothing under **site/** changes. The last successful deployment remains available if a later build fails. Check the repository's Actions tab for errors. To roll back, revert the responsible commit and push the revert to **master**.

## Obsidian LiveSync

Application code is isolated in **site/**. Before installing dependencies on another device, verify this vault's normal and hidden LiveSync selectors contain:

    ^02-领域知识/职业/(?:[^/]+/)*site(?:/|$)

Preserve existing selector entries. The website directory must be excluded while course notes and attachments remain eligible. **.gitignore** does not configure LiveSync. Follow **WEBSITE-HANDOFF.md** for the supported preflight procedure; the existing database cleanup is already complete.

Dependencies, generated output, and local QA artifacts are ignored by Git. Application source and the npm lockfile are committed.
